# Contributing

Thanks for helping. This is a small project, so the rules are short.

## Before you start

- Bugs: open an issue with the bug template. Include your OS version and what you expected.
- Ideas: open an issue with the feature template first, so we can agree on it before you write code.
- Security problems: do not open a public issue. See [SECURITY.md](SECURITY.md).

## Setup

Setup steps arrive with the first code. They will be: install the toolchain listed in `docs/design.md`, clone, then one command to run the app and one to run the tests.

## Pull requests

- One change per pull request. Keep it small enough to review in one sitting.
- Title in the form `type: what changed`, for example `fix: keep window position after restart`. Types: feat, fix, refactor, perf, docs, test, build, ci, chore.
- Say what you changed, why, and how you tested it. Say which checks you did not run.
- Add or update tests for behaviour you change.
- Never commit real host names, IP addresses, user names, tokens or screenshots that show them. Use `example-server`, `192.0.2.10` and `user` in examples and tests. CI runs a secret and personal-data scan on every pull request.
- If an AI tool helped write the change, say so in the pull request. That is fine; we just want to know.
